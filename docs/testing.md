# Testing

| Suite | Command | What it covers |
|---|---|---|
| Unit (Vitest) | `npm test` | Lifecycle state machine; human-readable IDs; permissions and gate roles; scoring profiles and evidence-capped confidence; unit economics, pricing, bundles, quantity discounts and recommendations; financial model; decision engine (sufficiency, kill/iterate/clone/scale, winner lift, configurable thresholds); command parser; CSV parsing and import validation; compliance screening; slugs and niche keys; **structured-output validation and retry behaviour**; every demo generator validated against its agent schema; evidence normalisation (fabricated refs downgraded); AES-GCM credential encryption; upload validation; export adapters (JSON, Next.js, Shopify CSV); fulfillment adapters; storefront theme safety; registry, prompt and payload consistency; queue and cost helpers |
| Integration (Vitest + local Supabase) | `npm run test:integration` | RLS isolation; viewer read-only; SQL ↔ TS lifecycle parity (all stage pairs) and gate-role parity; sequential codes; gated transitions and gated values blocked (including for the service role); gate decisions human-only, role-checked, reason-required and single-use; credentials unreadable; rate limiting; **Opportunity Scout workflow**; duplicate-research prevention; job dedupe; **approval → Brand Record**; **Brand Architect workflow**; **Creative Director + automatic compliance**; compliance flag → rejection; **product economics + assortment approval**; **store generation + launch + export**; growth → experiment → Analyst; clone and kill decisions; complete agent history; CSV imports (catalog, orders with financial rebuild, metrics) and search |
| E2E (Playwright) | `npm run build && npm run test:e2e` | Sign-up → onboarding → dashboard; login redirect; dashboard; **create research mission**; **approve opportunity**; **open brand**; **review design**; **storefront preview** (desktop and mobile, product page); command bar |

The integration and E2E suites need the local Supabase stack (`npm run db:start`) and `.env.local`. Integration tests skip automatically when Supabase is unreachable. E2E global setup (`scripts/e2e-setup.ts`) creates a fresh owner and runs the PL-0001 walkthrough so every screen has data. Playwright uses the Chromium bundled with `@playwright/test@1.56.1`.

All tests use the deterministic demo AI provider. No network AI calls are made.
